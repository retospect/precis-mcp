Orchestrator: a round is open (scripts/round status shows the base, which is what prod runs). Contract: get your reasonably timely work onto main with /qland as each piece is ready, then from your own tree run scripts/round in <sha> (or scripts/round none, or scripts/round eta <text> if a piece worth waiting for is close). Aim to mark within about 90 minutes. The mark is your status report: do not also message the orchestrator that you landed, are still working, or have nothing; message only what needs an answer or a decision. A change with a migration or safe_fetch.py cannot qland: say so with scripts/round eta and file a review-queue item. Do not deploy; the orchestrator gates the integrated main and deploys it pinned. The session MCP serves deployed code only, so a just-landed verb is not there until that deploy. After the deploy you get a ping to dogfood your landed work on prod.
Standing rule (Reto, 2026-10-03): build with subagents per AGENTS.md "Agent sizing" — your main loop keeps design and domain judgment; searches go to navigator/extract/Explore, decided edits to coder/test-author/documenter, test runs to test-runner, cluster reads to cluster-ops, bug tracing to root-cause, pre-ship review to reviewer; independent pieces run as parallel agents in one message; any agent that edits uses isolation worktree so it does not collide with your tree.

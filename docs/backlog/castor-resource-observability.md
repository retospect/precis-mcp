# Castor resource observability

Deliver both native low-resource alerts and bounded local incident evidence through the existing heartbeat and alert paths. Spec awaiting coordinator/source review; numeric values below are proposals for that review, not installed production defaults.

## Premises and overlap

- Retained Castor evidence proves kernel OOM kills with depleted Normal zones, and later NVRM `NV_ERR_NO_MEMORY` records; it does not prove the cause of the SSH command-channel stall, a workload leak, GPU-VRAM exhaustion or NAS involvement.
- PAM session opens and logind session creation demonstrate server progress; neither establishes client channel confirmation or command execution. Preserve stage observations separately, without timestamp-only PID/session attribution.
- `workers/heartbeat.py::run_heartbeat_pass` self-throttles at 60s; `start_heartbeat_thread` survives a slow worker rotation. `_collect_and_upsert` reports load/temp/activity/NAS, then capabilities; it has no kernel-event or allocator collector.
- `workers/capability_probe.py::_mem_free_bucket` already maps available RAM to soft `mem` buckets: `<10%` → 0, `<25%` → 1, otherwise 2. This affects heavy-job claim vetoes and `/factory`; this batch must not change that scheduling policy or its manual override.
- `store/_heartbeat_ops.py::record_heartbeat` replaces metadata except protected per-process namespaces. `record_heartbeat_history` stores load/temp only; it cannot silently become resource history.
- `deploy/roles/monitoring/templates/alert_rules.yml.j2::HighMemoryUsage` warns below 10% available RAM for 10m; Prometheus scrape/evaluation is 15s. The checked config has no Alertmanager routing; deployed alert delivery was not sampled in this spec turn.
- [self-healing-spine.md](self-healing-spine.md) parks richer T0 telemetry and a future governor; this item owns only the bounded resource/event slice, with no `host_samples` table or governor. [alert-failure-id-registry.md](alert-failure-id-registry.md) owns a future addressable rule catalogue; use stable producer fingerprints now without building that catalogue here.
- Existing sshd OOM protection, earlyoom and opt-in worker memory caps remain separate operational mechanisms: `deploy/roles/hardening/{defaults,tasks}/main.yml`, [oom-lockout-hardening](../runbooks/oom-lockout-hardening.md). OOM protection alone cannot guarantee a usable SSH command channel; update that guarantee in the runbook when shipping this item.

## Observation and policy contract

Each dimension reports `observed_at` UTC, monotonic sample time within the OS boot, units, source, availability (`ok`, `unsupported`, `denied`, `error`, `stale`), error/exit and any truncation. Use `/proc/sys/kernel/random/boot_id`, distinct from heartbeat's per-worker UUID. Never reuse an earlier numeric value as fresh after a failed read; reset dwell on a gap. Preserve alerts during unknown intervals.

Read `/proc/meminfo`, `/proc/pressure/memory`, selected `/proc/vmstat`, `/proc/zoneinfo`; convert kB to bytes and pages using the measured page size. Record total/available/swap, PSI some/full `avg10` percent and total microseconds, slab/reclaim counters, per-node/per-zone free/min/low/high plus protection/reserve context. A free-versus-watermark comparison is a screening signal, not a reconstruction of order/GFP/cpuset allocation success.

For at most eight validated cgroup-v2 paths covering worker, compute and SSH units plus ancestors, read `memory.current/max/high`, `memory.events`/`memory.events.local` where supported, `memory.stat`, `memory.pressure`, swap current/max. Preserve ancestor binding limits, hierarchy double-counting caveats, unlimited `max` and counter reset identity; missing cgroup-v2 is unsupported. Never reinterpret cgroup pressure as host OOM.

GPU dimension: NVRM allocation events are driver signals. Optional bounded `nvidia-smi` query reports device identity, memory used/total and rc; driver/unified-memory devices may have unsupported accounting. No GPU usage alert threshold is proposed without a valid device-specific baseline. Free swap or GPU metrics cannot negate a kernel OOM/NVRM event.

| Proposed policy / bound | Numeric contract | Evidence / review confidence |
|---|---|---|
| Sampling / freshness | Existing heartbeat interval, nominal 60s; resource values stale after 180s; enabled collector unavailable/stale for 300s raises warn. | Reuse cadence; 3/5 missed beats tolerate transient failure. Cost and false positives require deployment sample. |
| Aggregate RAM warn | `MemAvailable/MemTotal <25%` continuously 300s; clear at `>=30%` continuously 300s. | Existing soft warn boundary; 5-point hysteresis/dwell are proposed, not measured Castor baselines. |
| Aggregate RAM critical | `<10%` for two fresh samples at least 60s apart; leave critical at `>=15%` continuously 300s, retaining warn until its clear boundary. | Existing veto/Prometheus boundary; faster native critical duration proposed to give operator headroom, no claim-veto change. |
| Normal-zone screening | Per node: `free<=low` for two fresh samples → warn; `free<=min` once → critical; clear after `free>high` continuously 300s. | Actual failure slices show free near/below min despite ample swap; kernel-provided thresholds avoid an invented absolute-GiB limit. Must review NUMA/protection semantics on Castor before enablement. |
| Host/cgroup PSI | `some avg10>=10%` or `full avg10>=1%` for 120s → warn; clear both below 5% / 0.5% for 300s. | Diagnostic sustained-stall proposal; no incident baseline exists. Shadow evaluation first; no critical paging from PSI alone. |

No cap changes. |
| Confirmed kernel/NVRM event | Immediate critical, no metric dwell; open historical event alert until operator acknowledgment. | Verified retained signatures; causal attribution explicitly excluded. |

| Observer work | One host-local collector lock, no wait on contention; <=8s total optional work/tick; <=2 child processes alive, each terminated only by its own timeout. | Bounds observer interference; child-deadline enforcement never signals host workloads. | Cheap context ring | One summary/minute, <=8KiB each, last 30 samples / 240KiB total. | Gives at most 30m coarse pre-incident context; no historical stack or sub-minute reconstruction. |

| Low local disk | Local target filesystem available `<1GiB` **or** `<5%`: disable raw/snapshot writes, retain <=32KiB in-memory failure summary; attempted state error explicit, no cursor advance without durable receipt. | Reserve far larger than observer budget; local-only statvfs on provisioned device. Review filesystem/device identity and inode availability. |

Time dwell requires fresh monotonic samples covering the stated duration; sample gaps reset it. Unsupported dimensions never enter/resolve resource alerts. Policy configuration validates units, ordering and caps; invalid policy disables only the affected dimension and raises coverage warning. Preserve actual values/reason at alert transition, then aggregate minima/maxima between throttled updates.

Threshold review is required for the proposed durations/PSI/cgroup screening and local budgets. Initial enabled Castor baseline: one cheap sample after verified deployment; seven days of bounded summary retention for review, with provisional PSI/cgroup-utilization warnings shadow-only until coordinator accepts measured false-positive/cost results. Actual event alerts, existing-boundary aggregate alerts and reviewed zone screening need no stress experiment. No silent promotion of shadow rules.

## Journal events, counts and discontinuities

- Read kernel JSON records with real journal cursor, `_BOOT_ID`, realtime/monotonic timestamps and collector rc/stderr. Match confirmed `Out of memory: Killed process` / cgroup-kill records; count each unique kill record once. Request/`oom-kill:`/zone lines supply context, not additional kill counts. NVRM messages containing `NV_ERR_NO_MEMORY` count unique allocation-failure records; preserve `_memdescAllocInternal` context when present. Multiline parser fixtures define the exact anchored grammar; unrelated errors never match.
- Alert source `resource-events`; fingerprint `<host>:<os_boot>:<kernel-oom|cgroup-oom|nvrm-allocation>`. Retain distinct `journal_record_count`, confirmed-kill count, cgroup counter delta, first/last event UTC, first/last cursor, coverage and artifact ID. Journal kill records and cgroup counter deltas are complementary observations, never summed into a claimed global exact kill count.
- Pressure source `resource-pressure`; stable fingerprint `<host>:<dimension>:<node-zone-or-unit-key>`. Coverage source `resource-observer`; fingerprint `<host>:<component>`. No PID/count/message/time in pressure fingerprints. Per-boot event identity is intentional historical separation; metadata records policy version.
- Atomic local receipt commits cursor and cumulative counts together after bounded raw retention; file+directory durability precedes advancement. Use monotonic sequence per boot and absolute cumulative counts for DB replay; retain only latest unsent summary per family (<=64), never an unbounded outbox. DB updates reject older sequence within that boot. Prior-boot replay updates only that boot's event alert; resource summary always uses this tick's measured OS boot, never an old outbox item. No cross-filesystem/DB exactly-once claim: retried absolute summary is idempotent, while alert transport sightings remain coarse.
- Restart resumes the durable cursor and existing counts. Invalid/vacuumed cursor marks an explicit coverage gap; read retained records from last accepted UTC with bounded overlap and dedup by boot/cursor. If continuity cannot be demonstrated, counts are lower bounds with gap start/end; never claim exact reconstructed totals. Preserve raw/cursor segments subject to the stated cap, with sequence/checksum manifest; crash replay beyond retained IDs is uncertain, not silently counted twice.
- First installation starts a bounded last-10m window of the current boot, disclosing omitted earlier history; no unsolicited previous-boot forensic scan. New OS boot gets a fresh cursor/count namespace; seal old counts/coverage without clearing old event alerts. Keep state for current and one prior boot within its cap; DB retains published history.
- A capped pass advances only through fully decoded/receipted records and reports backlog. Partial message/byte truncation retains bounded prefix plus omitted-byte/unknown-tail metadata; do not treat an unparsed tail as healthy or advance past an incomplete record. An oversized record that cannot progress must be explicitly marked skipped/gap in a durable receipt, preventing endless replay.
- Access loss, nonzero rc, timeout, clock regression, vacuum/rotation and disk failure produce distinct coverage states. Recovery starts a new verified coverage interval, not an inferred all-clear. Only pressure fingerprints resolve on measured hysteresis; empty/error journal output cannot resolve historical events.

## Snapshot and SSH evidence

Provision `/var/lib/precis/resource-observer` on a verified local filesystem; collector rejects symlink/path escape and remote filesystem types. No NAS traversal, `df`/`du`, mount walk, environment, credential, full argv, process memory or model/DB payload reads. Never route raw collection through RTK as the parser: summaries retain independently verified raw excerpts, rc, byte/entry counts and truncation.

Artifact manifest: UTC start/end, hostname, OS/kernel, OS boot, installed release identity already available locally, trigger IDs/policy, component argv template (no private values), exit/timeout, selected fields, bytes/records/omissions, sampling span and checksum. Include cheap ring, meminfo/vmstat/zones/PSI, bounded known cgroups, optional GPU result, selected PID/PPID/start ticks/state/comm/RSS/swap/wchan and permitted stacks. RSS is not unique physical ownership; enumerate/selection omissions stay visible.

SSH context reads a bounded recent journal slice (last10m, <=128 entries / 256KiB) for SSH and logind units, sharing snapshot deadline/byte cap. Extract authentication accepted, PAM open/close, logind create/remove and any actually logged channel/command stage; default SSH logging may omit channel detail. Keep PID/session ID where emitted and redact account/address/key details before retained safe output; raw allowlisted kernel resource records stay local. Never enable debug SSH logging or probe a new login in this batch. A future trusted client may supply its separately bounded handshake/channel/command-marker receipt; no client receipt is fabricated by the observer.

Collection is after a qualifying signal, not proof of its cause. A snapshot delayed by pressure is labeled with actual collection times, not backdated to the event. Capturing stacks is optional/denied when privilege is unavailable; all partial results remain useful without broad fallback access.

## Privilege and failure budget

- Ordinary metrics/local state use the worker's existing `deploy` account. Source hardening currently grants deployment `NOPASSWD: ALL`; neither that configuration nor the earlier one-off journal read proves safe ongoing worker privilege. Do not give the worker a journal group or new blanket root/CAP_SYS_PTRACE capability.
- Preferred privileged seam: one root-owned, non-deploy-writable installed helper with no shell, imports only root-owned stdlib/install paths, isolated interpreter, and a fixed validated JSON request (`kernel-events` or `incident-context`). `sudo -n` may invoke only that helper; read roots, units, journal fields, boot/cursor syntax, selected PID membership, all caps/timeouts and redaction are enforced inside it. Never accept paths, commands, Python modules or environment overrides. Existing broad deployment sudo policy is unchanged by this task; helper constrains what the observer invokes, not an account-wide security boundary.
- Helper may read kernel/SSH/logind journal and selected `/proc/<pid>/stack`; it never writes root state, starts services or signals workloads. Output crosses into deploy-owned local storage only after validation/redaction. If narrower access cannot cover the required reads, return denied and missing evidence; expanding access needs separate reviewed scope, not a silent fallback to `sudo journalctl`/shell.
- Local observation runs independently of DB success after the primary heartbeat attempt; failures do not block basic heartbeat or spawn retries in the tick. Latest safe summary/coverage publishes through existing store/alerts when available. Host-local collector lock and persisted next-due avoid worker/pass/timer duplication; only enabled physical-host owner collects, no container/compute duplicate.
- A local observer cannot collect when its worker/OS is frozen or lost; nursery host-dark and existing Prometheus are backstops. This batch adds no out-of-band paging guarantee. Missing ops target/bot or DB is reported as delivery unavailable, never claimed as delivered.
- Catch bounded component failures, rate-limit error logging to once/component/900s plus transitions, retain error counts. On disk-full stop writing instead of pruning outside owned retention. No auto-restart, power cycle, kill policy, memory/swap/GPU tuning, NAS change, placement/governor/role change or science/production0.22 change.

## Acceptance and review gate

1. Sanitized supplied multiline OOM/Normal-zone and NVRM fixtures produce separately classified events, correct unique-record/kill counts and bounded raw provenance; request/context lines do not double-count. Unrelated errors and RTK zero-recognized-error summaries cannot alter raw classification. Preserve rc/nonzero/timeout and entry-versus-line-versus-byte limits.
2. Crash/restart, concurrent heartbeat/pass calls, OS boot change, repeated cursor, vacuum, oversized message, burst, exhausted caps, stale DB replay and collector access loss exercise durable state/counts and honest coverage gaps. No duplicate fresh page from the same observed episode; manual event resolution does not resurrect from replay. Unknown coverage never auto-resolves.
3. Boundary fixtures verify RAM dwell/hysteresis, depleted Normal zone despite ample swap, cgroup ancestor limit/counter reset, PSI and GPU unsupported/stale paths. Scheduling mem buckets/overrides and existing Prometheus expressions remain unchanged. Shadow policy cannot page or promote itself.
4. Snapshot/process/child/time/byte/file/retention/free-space limits hold under synthetic bursts and partial failures; no NAS/path escape, argv/environment/key leak, unbounded stack scan or workload signal. Multi-process observer lock cannot block heartbeat; failed collector leaves fresh liveness with visible degraded coverage.
5. Focused `scripts/test` regression suites cover observer parsers/policies/state, heartbeat merge/thread behavior, nursery coverage, alerts and affected web rendering; Ruff and container typecheck pass. Independently review helper validation, output redaction, deployment path/ownership and resource costs; coordinator schedules full suite/release gate. No tests or product implementation in this spec turn.
6. After coordinator announces exact verified deployed SHA: one cheap real Castor observation proves PID/OS boot, units, timestamps, coverage/cost and configured policy; read its native alert detail and browser health display. Bind native status once if release proof requires it. Validate event path with sanitized fixtures or explicitly marked synthetic data in isolated test storage, never a fake production incident or induced OOM. Observe actual ops delivery only through the already authorized configured route; no repeated readiness/status loops or all-kind scan.
7. Review before enablement: Castor local target filesystem/ownership, kernel/zone format and page size, selected cgroup/unit layout, journal privilege/retention, GPU metric support, helper interpreter ownership and current ops target availability. Missing facts remain explicit deployment dependencies; no new live collection is authorized by this spec. Coordinator owns implementation assignment, monitored promotion and release sequencing.
